# Sales Data Cleaning and Quality Verification

Python scripts for cleaning sales workbooks and checking data quality before analysis. Rules are driven by `Verification_Configuration.xlsx`.

## Included files

| File | Purpose |
| --- | --- |
| `01_Data_Cleaning.py` | Clean configured sheets and export a new workbook |
| `02_Verification.py` | Verify the cleaned workbook and print results |
| `Verification_Configuration.xlsx` | Column types, mandatory fields, uniqueness, non-negative values, allowed values, and date relationships |
| `Data_Cleaning_Portfolio_Sample.xlsx` | Before/after examples for two periods, with 100 data rows per sheet |
| `Data_Quality_Verification_Report(1).xlsx` | Previously prepared example report, not regenerated by the scripts |
| `requirements.txt` | Python dependencies |

The included workbook is a portfolio sample, not the original client dataset. Sample results describe only the included records.

## Setup

Use Python 3.10 or later. Download and extract this repository, then open a terminal in its folder.

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
```

On Windows, activate with `.venv\Scripts\activate` and use `python` instead of `python3` if needed.

## Run the included sample

```bash
python3 01_Data_Cleaning.py --sample
python3 02_Verification.py --sample
```

Sample mode reads only the two Before sheets, skips their title rows, and maps their names to the configuration's Year sheet names. It creates `Cleaned/portfolio_sample_cleaned.xlsx`. The After sheets are reference examples and are not used as input.

Verification prints to the terminal. To save its output:

```bash
python3 02_Verification.py --sample > sample_verification.txt
```

## Run the full workbook

Place `online_retail_II.xlsx` beside the scripts. This full input is not included. Its worksheet names and columns must match the configuration.

```bash
python3 01_Data_Cleaning.py
python3 02_Verification.py
```

This creates and verifies `Cleaned/online_retail_II_cleaned.xlsx`. Sample and full outputs have separate filenames. Re-running cleaning replaces the corresponding generated output.

For another dataset, update the input filename and configuration. Only matching sheets are processed. Cleaning stops if no sheets match. Verification returns a nonzero exit status if no sheets are verified or a check group fails.

## Cleaning scope

- Standardize column spacing and replace hyphens with underscores.
- Remove duplicate column names, exact duplicate rows, and fully empty rows/columns under the agreed cleaning rules.
- Remove ASCII control characters and excess whitespace from text.
- Standardize missing-value markers.
- Convert configured numeric and date fields and print conversion failures.
- Apply title case to configured category fields.
- Export formatted dates, filters, frozen headers, and adjusted column widths.

Missing values remain missing internally. Excel exports use `NA` for non-date fields and `NAT` for date fields. Verification reads those markers as missing. Non-ISO date strings use a day-first assumption. Invalid conversions become missing, so review conversion messages before analysis. Numeric cleaning assumes comma thousands separators and decimal points; adapt it for other formats.

## Verification and business exceptions

Checks cover duplicates, configured types, mandatory fields, missing values, empty rows/columns, whitespace, control characters, column names, non-negative rules, allowed values, and date relationships.

Business review counts are separate:

- Zero price: `Price == 0`.
- Near-zero price: `0 < Price <= 0.1`, in the dataset's price currency.
- Zero quantity: `Quantity == 0`.

Review counts do not automatically fail verification. A PASS means configured checks passed, while business exceptions can still require decisions. Empty allowed-value and date-relationship configurations are reported as having no rules.

## Client decisions before analysis

- Retain transactions without Customer IDs for overall sales analysis. Customer metrics should cover identified customers only and disclose the percentage of transactions without an ID.
- Use StockCode for grouping after reviewing its consistency and conflicting descriptions.
- Preserve zero/near-zero prices until corrections are confirmed. Detailed exception summaries should include quantities and example invoices.
- Report confirmed bad-debt adjustments separately and review other negative prices before classification.

These are analysis requirements. The scripts do not calculate customer metrics, resolve product-description conflicts, classify bad debts, or generate the detailed exception workbook automatically. The uploaded report is an example deliverable.

## Regression checks

```bash
python3 -m unittest discover -s tests -v
```

Checks cover missing/nonnumeric fields, price boundaries, missing rule-dependent columns, and zero verified sheets.
